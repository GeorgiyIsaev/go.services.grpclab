ClientServerStream

Один вызов client.StreamRandom(ctx, req) — и всё.

Сравните с Unary-клиентом: там было client.GetRandom(ctx, req), который сразу возвращал ответ. Здесь возвращается объект-стрим, а сообщения приходят позже, по одному.

stream.Recv() в цикле. Это сердце клиента. Каждый вызов:

блокируется, пока не придёт следующее сообщение,

возвращает (*StreamRandomResponse, nil) если сообщение пришло,

возвращает (nil, io.EOF) когда сервер корректно закрыл поток,

возвращает (nil, err) при любой другой проблеме.

errors.Is(err, io.EOF) — стандартный способ отличить «нормальное завершение» от ошибки. io.EOF — это не сбой, а сигнал «отправитель закончил». Всегда проверяйте именно через errors.Is, а не через err == io.EOF: gRPC может оборачивать ошибки, и прямое сравнение не сработает.


Отмена через context. Когда клиент нажимает Ctrl+C, мы вызываем cancel(). Это не просто «выход из программы» — gRPC отправляет серверу специальный сигнал отмены, и сервер видит это в stream.Context().Done(). На сервере в StreamRandom есть select по этому каналу, поэтому он сразу завершит работу и не будет «слать в пустоту».

Отличие ctx.Err() != nil от других ошибок. Если stream.Recv() вернул ошибку, и при этом ctx.Err() != nil — значит, вы сами отменили контекст, и ошибка — следствие. Это нормально, не нужно падать с log.Fatalf. А вот если ошибка пришла, а контекст жив — это уже настоящая проблема (сервер упал, сеть порвалась), тут можно и завершиться.

Тесты
1. Бесконечный поток. Поставьте Count: 0 в клиенте: Сервер не остановится сам.
2. Убейте сервер. С Count: 0, но убив сервер (Ctrl+C в первом терминале), вы увидите в клиенте ошибку вроде:
``` ошибка приёма: rpc error: code = Unavailable desc = ...```
3. Запустите два клиента одновременно. В двух дополнительных окнах запустите клиент. У каждого — свой независимый поток, со своим расписанием. Сервер обслуживает их параллельно. Это хорошо показывает, что каждый вызов Server Streaming живёт своей жизнью.
4.  Уменьшите интервал до 1 секунды. Через grpcurl тоже удобно смотреть:

```  grpcurl -plaintext -d "{\"interval_seconds\": 1, \"count\": 3}" localhost:50051 random.Random/StreamRandom``` 

5. Поставьте IntervalSeconds: 0 — сервер применит дефолт 5 секунд (см. код сервера: if interval <= 0 { interval = 5 * time.Second }). Полезно, чтобы понять, как сервер обрабатывает «пустые» параметры.


ИТОГ

Один вызов — много ответов. Это и есть Server Streaming.

Клиент читает в цикле for { Recv() }. Никаких таймеров на клиенте — расписание задаёт сервер.

io.EOF — это нормальное завершение потока, а не ошибка.

Отмена через контекст работает в обе стороны. Клиент нажал Ctrl+C → сервер увидел. Сервер вернул nil из метода → клиент увидел io.EOF.

Server Streaming — это именно то, что вы изначально описывали словами «клиент слушает, сервер шлёт каждые 30 секунд». Теперь это работает по-настоящему.
